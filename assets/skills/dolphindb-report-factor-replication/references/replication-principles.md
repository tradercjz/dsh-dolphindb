# 因子复现必须遵守的原则

## Skill 介绍

本 Skill 用于约束研报因子复现过程中的研究原则、数据原则和实现原则。生成或修复因子代码时，必须避免未来数据泄露、样本选择偏差、字段幻觉、标签污染和输出结构不一致。

## 数据源原则

1. 因子计算必须使用历史数据，不能使用未来时点才知道的信息。
2. 因子在 `tradeTime = t` 的值，只能依赖 `t` 或 `t` 之前已经可获得的数据。
3. 若研报因子用于预测未来收益，未来收益只能作为评价标签，不能进入因子值计算。
4. 若使用财务、公告、行业、指数成分、权重等数据，应以可获得日期为准，而不是报告期、公告后修正值或回填值。
5. 数据源字段必须来自真实字段定义和样例数据，不能凭常见命名自行创造字段。
6. 数据粒度必须满足因子公式需要；分钟窗口不能用日线数据强行复现。

## 防未来数据泄露

### 禁止场景

- 用未来收益、未来涨跌幅、未来成交量构造当前因子。
- 用全样本均值、全样本标准差对历史时点做标准化。
- 用未来日期的行业分类、市值、指数成分或财务数据回填历史。
- 在滚动窗口中包含预测目标期的数据。
- 为了让结果更稳定而在因子计算阶段引用评价结果。

### 正确做法

- 时间序列滚动窗口只看当前及过去窗口。
- 横截面标准化只在同一时点的可交易样本中进行。
- 训练、筛选、衍生策略选择不能污染最终评价样本。
- 对财务数据使用公告日或可交易日对齐。
- 对停牌、缺失、异常样本明确过滤或置空。

## 样本与口径原则

1. 证券池、行业、市值、指数成分等样本口径必须明确。
2. 若研报未提供证券池，应在说明中标记为待外部过滤，不要自行假设。
3. 横截面因子应避免把不可交易、停牌或严重缺失样本纳入排名。
4. 分组、中性化、标准化必须在同一时点内完成。
5. 多市场、多品种、多频率数据混用时，必须说明对齐方式。

## 计算实现原则

1. 先理解研报公式，再做字段映射和代码生成。
2. 不得因为字段缺失而随意替换为相似但含义不同的字段。
3. 分母为 0、空值、窗口不足、极端值必须显式处理。
4. 时间序列计算前应按证券和时间排序。
5. 横截面计算时应按时间分组，必要时按行业或其他分组变量细分。
6. 最终输出必须统一为 `tradeTime`, `securityId`, `factorname`, `value`。
7. `factorname` 必须与当前复现因子对应。

## 因子与评价的边界

1. 因子代码只计算因子值，不计算未来收益标签。
2. 因子评价指标如 IC、IR、t-stat、p-value、分组收益、换手率，不应进入因子本身。


## 常见违规信号

- 代码中出现 `futureReturn`、`label`、`target` 等字段参与 `value` 计算。
- 滚动窗口没有按时间排序。
- 标准化使用全表 `avg` 或 `std`，没有按 `tradeTime` 或历史窗口分组。
- 字段不在 `coldefs` 或 `testsql` 中出现。
- 输出列包含除 `tradeTime`, `securityId`, `factorname`, `value` 之外的额外列。
- 为避免报错删除核心计算，只返回常数、随机数或简单价格列。

## 检查清单

- 因子值是否只使用历史可获得数据。
- 是否没有把未来收益或评价标签放入因子计算。
- 字段是否来自真实数据源。
- 数据粒度是否满足研报公式。
- 滚动窗口和横截面分组是否符合时间边界。
- 最终输出列是否完全符合统一结构。
