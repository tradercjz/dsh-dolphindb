# 场景 05：对整表、整列或一批同类对象进行同一处理时，仍手工展开

场景介绍：

代码明明在处理整张表、整列或一批同构对象，却还保留遍历列名、逐列重排、逐对象手工映射。这个场景优先检查：整表行重排、统一列变换、多对象同构映射。若主问题已经变成查询结果整形、长宽转换或查询内打包，转到 `scene-09`。

以下是一些典型的例子：

## 1. 整表行重排仍逐列处理

目标：把整张表按行倒序。

低效写法：

```dos
for(x in t.colNames()){
    t[x] = t[x].reverse()
}
```

分析：目标是整表按行重排，代码却逐列处理。这样写容易把“整表行操作”误写成“每列各算各的”。

解决方案：

```dos
t = t[t.rows():0]
```

分析：这里直接按行号重排整张表。所有列会一起保持行关系。

## 2. 同一种列变换仍手工遍历列名

目标：对表的每一列做同一种变换。

低效写法：

```dos
for(x in t.colNames()){
    t[x] = reverse(t[x])
}
```

分析：每列执行的是同一个函数，循环只是在重复列级调用。

解决方案：

```dos
re = reverse:V(t)
```

或者：

```dos
re = byColumn(reverse, t)
```

分析：列级统一处理优先切到 `:V` 或 `byColumn`。这类任务不需要自己遍历列名。

## 3. 多对象同构映射仍手工遍历

目标：对一批对象应用同一个函数。

低效写法：

```dos
t = table(1 2 3 as a, 4 5 6 as b, 7 8 9 as c)
cols = [t.a, t.b, t.c]
re = array(INT)
for(x in cols){
    re.append!(count(x))
}
```

分析：函数没有变，变化的是输入对象。循环只是在重复同一种映射。

解决方案：

```dos
t = table(1 2 3 as a, 4 5 6 as b, 7 8 9 as c)
cols = [t.a, t.b, t.c]
re = each(count, cols)
```

分析：这种写法直接把“对每个对象做同一件事”表达出来。多对象同构映射优先查 `each`。

## 4. 函数索引

| 函数 / 模式 | 什么时候查 | 解决什么问题 |
| --- | --- | --- |
| 表索引 / 行号序列 | 整表行重排仍逐列处理 | 整表按行重排 |
| `byColumn` / `:V` | 每列要做同一种变换 | 列级统一处理 |
| `each` | 一批对象做同一种映射 | 同构对象映射 |
| `replaceColumn!` / `reorderColumns!` / `rename!` | 表列结构或列内容整体调整 | 整列修改 |
