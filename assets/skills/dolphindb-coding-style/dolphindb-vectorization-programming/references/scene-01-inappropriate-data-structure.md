# 场景 01：对批量数值数据进行计算时，数据结构选择不合适

场景介绍：

数据一开始就落在了不合适的结构里，或者进入计算前没有切到更合适的对象形态。代码看起来已经在批量对象上计算，实际还在错误的承载结构、错误的计算入口上绕路。这个场景优先检查：一维数值数据有没有落成 `ANY VECTOR`，等长二维数值数据有没有直接进入矩阵路径，不等长同类型二维数据有没有继续拆成多列或普通元组。

以下是一些典型的例子：

## 1. 一维数值数据落成 `ANY VECTOR`

目标：对一维数值序列做累计。

低效写法：

```dos
v = []
v.append!([1,3,5,7,9])
re = cumsum(v)
```

分析：`[]` 初始化出来的是元组。`append!` 之后，`v` 仍然是 `ANY VECTOR`。`cumsum` 用在这种对象上，走不到强类型向量的紧凑存储路径。

解决方案：

```dos
v = array(INT)
v.append!([1,3,5,7,9])
re = cumsum(v)
```

分析：`v` 变成了强类型向量。后续累计、聚合、算术都能沿常规向量路径继续执行。

## 2. 等长数值二维数据没有直接进入矩阵路径

目标：得到面板型结果，后续还要继续做二维数值计算。

低效写法：

```dos
re = select avg(price) from t group by timestamp, sym
```

分析：这条语句得到的是表结果。如果下游还要继续做面板型计算，后面还要再整形成二维结构。数据本体已经适合矩阵承载，却多走了一次表结果路径。

解决方案：

```dos
m = exec avg(price) from t pivot by timestamp, sym
```

分析：上游直接产出矩阵。后续按行、按列、按截面的数值计算都更顺。矩阵就是这类等长二维数值数据的自然承载结构。

## 3. 不等长同类型二维数据继续拆成多列保存

目标：保存并处理多档同构字段。

低效写法：

```dos
select time, sym, bid1, bid2, bid3, bid4, bid5 from quotes
```

分析：五档买价本质上是一组同类型二维数据。拆成多列以后，后续列合并、逐行派生、统一处理都会更麻烦。

解决方案：

```dos
select time, sym, fixedLengthArrayVector(bid1, bid2, bid3, bid4, bid5) as bid from quotes
```

分析：同构字段被合成了一个数组向量字段。后续如果要做逐行统计、统一派生、入库存储，路径会更顺。

字符数组落到列式元组也是同一路线，这里先不展开。

## 4. 纯数值表仍停留在表语义上硬算

目标：把向量 `v` 作用到表 `t` 的每一行。

低效写法：

```dos
v = 1 2 3
t = table(rand(100, 1000000) as a, rand(100, 1000000) as b, rand(100, 1000000) as c)
re = byRow(mul{v}, t)
```

分析：当前任务本质上是纯数值二维计算。`byRow` 作用在表上时，按行遍历，每行进入的是字典对象。数据已经适合矩阵路径，代码却还留在逐行表语义上。

解决方案：

```dos
v = 1 2 3
t = table(rand(100, 1000000) as a, rand(100, 1000000) as b, rand(100, 1000000) as c)
re = each(mul, v, matrix(t))
```

分析：先把表切成了矩阵。计算入口切到了更适合纯数值二维计算的路径上。参考资料对同一任务做过路线对比，矩阵方案更快。

## 5. 自定义向量函数直接拿去算表

目标：对表的每一列做去均值。

低效写法：

```dos
def myDemean(x){
  return x - avg(x)
}

t = table(1 2 3 4 as val1, 5 6 7 8 as val2)
myDemean(t)
```

分析：`myDemean` 在向量上成立。表对象进来以后，系统不会自动把这个自定义函数当成按列函数使用。继续在这个入口上硬算，结果通常是报 shape 不兼容，或者被迫回到手工拆列路径。

解决方案：

```dos
def myDemean(x){
  return x - avg(x)
}

t = table(1 2 3 4 as val1, 5 6 7 8 as val2)
re = myDemean:V(t)
```

或者：

```dos
re = byColumn(myDemean, t)
```

分析：这里先把函数入口改对了。`:V` 和 `byColumn` 都是在告诉系统：这个函数要按列作用在复杂对象上。

## 6. 函数索引

| 函数 / 模式 | 什么时候查 | 解决什么问题 |
| --- | --- | --- |
| `array(TYPE)` | 一维数值序列初始化后混成 `ANY VECTOR` | 恢复强类型向量入口 |
| `flatten` | 一维对象已经落成可统一类型的复杂形态 | 回到常规向量路径 |
| `matrix(t)` / `matrix(t.col(...))` | 纯数值表要切到二维数值计算 | 表转矩阵 |
| `reshape` / `v $ m:n` | 向量天然对应等长二维结构 | 向量转矩阵 |
| `pivot by` | 上游就能直接产出面板型结果 | 直接生成矩阵或宽结果 |
| `array(TYPE[])` | 不等长数值二维数据需要自然承载结构 | 创建数组向量 |
| `fixedLengthArrayVector` | 多列同构字段要合并 | 多列转数组向量字段 |
| `byRow` / `:H` | 任务确实要按行作用在二维对象上 | 显式行入口 |
| `byColumn` / `:V` | 任务要按列作用在二维对象上 | 显式列入口 |
| `values()` / `flip()` | 当前任务更适合列级桥接 | 表转列级元组或字典 |
