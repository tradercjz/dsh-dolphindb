# 场景 03：函数作用在函数集合或接口上

## 目录

1. 模块：组织和复用函数集合
2. 函数视图：暴露和管控函数接口
3. 模块与函数视图的边界

## 适用任务

当前任务需要组织一组函数、复用函数集合、发布函数接口、管理命名空间、控制权限或支持跨节点调用。

## 入口选择

| 任务 | 常用机制 | 判断标准 |
| --- | --- | --- |
| 组织通用函数集合 | 模块 | 需要命名空间、复用或源码发布形式 |
| 会话内使用模块函数 | `use` | 当前会话需要导入模块 |
| 发布 `.dom` 模块 | `saveModule` | 需要交付模块并保护源码 |
| 系统级加载模块 | `loadModule` | 需要所有会话可见 |
| 节点启动加载模块 | `preloadModules` | 需要节点或集群启动时加载 |
| 暴露受控函数接口 | 函数视图 | 需要权限控制、数据库访问封装或跨节点访问 |
| 注册函数视图 | `addFunctionView` | 将函数加入函数视图体系 |
| 授权函数视图 | `grant(..., VIEW_EXEC, ...)` | 允许用户执行指定函数视图 |
| 修改函数视图 | `dropFunctionView` 后重新注册 | 函数视图定义不能原地修改 |

## 1. 模块：组织和复用函数集合

模块适用范围：

- 通用处理逻辑集合。
- 需要命名空间管理的函数集合。
- 需要以 `.dos` 或 `.dom` 形式复用的代码。
- 需要将一组函数作为统一交付单元的场景。

判断规则：

- 模块文件后缀为 `.dos` 或 `.dom`，第一行必须是 `module` 声明。
- 模块名称必须与模块文件名一致；多级目录通过 `::` 形成命名空间。
- 模块中除函数定义、模块声明语句和模块导入语句外，其他代码会被忽略。
- 模块目录由配置参数 `moduleDir` 指定；未找到时，系统按 home 目录、工作目录、可执行文件目录查找。
- 目标是代码复用或命名空间管理时，优先选择模块。
- 目标是隐藏源码时，可将 `.dos` 模块发布为 `.dom`。
- 目标是所有会话可见时，使用 `loadModule` 或 `preloadModules`。
- 目标是权限控制或数据库访问接口时，不应只依赖模块。

### 例 1：定义模块

```dos
module fileLog

def appendLog(filePath, logText){
    f = file(filePath,"a+")
    f.writeLine(string(now()) + " : " + logText)
    f.close()
}
```

模块声明提供命名空间，模块内部承载函数定义。

### 例 2：导入并调用模块函数

```dos
use fileLog
appendLog("mylog.txt", "test my log")
fileLog::appendLog("mylog.txt", "test my log")
```

`use` 将模块导入当前会话。需要避免名称冲突时，使用 `moduleName::functionName` 调用。

### 例 3：将 `.dos` 模块发布为 `.dom`

```dos
saveModule("fileLog", overwrite=true)
```

`.dom` 用于模块交付和源码保护；权限控制应由函数视图或其他权限机制承担。

注意事项：

- `.dos` 内容变化后，需要重新执行 `saveModule` 生成新的 `.dom`。
- `.dom` 只序列化依赖模块名称，不序列化依赖函数定义；移动或加载 `.dom` 时，应同时处理依赖模块。
- 同一目录存在同名 `.dos` 和 `.dom` 时，系统只加载 `.dom`。

### 模块加载方式

| 方式 | 作用范围 | 适用场景 |
| --- | --- | --- |
| `use` | 当前会话 | 交互式开发、会话级使用 |
| `loadModule` | 系统初始化脚本 | 模块函数需要对所有会话可见；不能在命令行或 GUI 中执行 |
| `preloadModules` | 节点或集群配置 | 节点启动时自动加载模块；集群中 controller 和 datanode 应加载相同模块 |

系统级加载注意事项：

- 通过 `loadModule` 或 `preloadModules` 加载后，模块函数类似内置函数，对所有会话可见。
- 通过 `remoteRun` 或 `rpc` 调用这类函数时，远程节点也必须加载对应模块。
- 系统级加载后，调用模块函数时使用绝对命名空间。

## 2. 函数视图：暴露和管控函数接口

函数视图适用范围：

- 数据库访问封装。
- 带权限控制的计算接口。
- 跨节点可见的统一函数入口。
- 面向用户或外部系统的受控调用接口。

判断规则：

- 目标是对外提供数据访问或计算入口时，优先选择函数视图。
- 用户不应直接访问底层表时，用函数视图封装查询。
- 分布式数据库相关函数视图通常由系统管理员在控制节点注册。
- 函数视图持久化在分布式数据库中，添加后可在任意节点执行。
- 需要授予执行权限时，使用 `grant(..., VIEW_EXEC, ...)`。
- 函数视图需要修改时，先 `dropFunctionView`，再重新 `addFunctionView`。

### 例 4：封装数据库访问

```dos
def getSpread(s, d){
   return select avg((ofr-bid)/(ofr+bid)*2) as spread from loadTable("dfs://TAQ","quotes") where symbol=s, date=d
}
addFunctionView(getSpread)
grant("user1", VIEW_EXEC, "getSpread")
```

用户通过函数视图执行受控查询，不需要直接拥有底层表权限。

### 例 5：将模块加入函数视图体系

```dos
addFunctionView("fileLog")
grant(user1, VIEW_EXEC, "fileLog::*")
```

模块负责组织函数集合，函数视图负责发布接口并配置执行权限。

一旦将模块添加为函数视图，后续授权或删除应以模块为单位处理。

### 修改函数视图

```dos
dropFunctionView("getSpread")
```

函数视图定义不能原地修改。更新定义时，删除旧视图后重新注册。

## 3. 模块与函数视图的边界

模块与函数视图都能组织函数，但职责不同：

- 模块：函数集合复用、命名空间、发布形式、源码保护。
- 函数视图：数据库访问封装、接口暴露、权限控制、跨节点调用。

推荐组织方式：

1. 通用算法写入模块。
2. 数据访问与授权入口写成函数视图。
3. 函数视图内部调用模块函数。

## 典型使用场景

- 内部分析人员复用一组工具函数时，优先考虑模块和 `.dom` 发布形式。
- 终端用户或外部系统需要受控访问数据库时，优先考虑函数视图。
- 同一套计算逻辑既要复用又要授权时，将通用计算放入模块，将对外入口注册为函数视图。

## 选择清单

处理“函数作用在函数集合或接口上”的任务时，按以下顺序判断：

1. 当前目标是组织通用逻辑，还是暴露数据库访问接口。
2. 是否需要权限控制。
3. 是否需要跨节点可见。
4. 是否需要隐藏底层表结构或源码细节。
5. 是否需要将模块函数统一纳入函数视图授权体系。
