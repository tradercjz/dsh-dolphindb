# 场景 01：函数作用在数据上

## 目录

1. 逐项或组合应用
2. 按行、按列或结构方向处理数据
3. 递推、累计和相邻关系
4. 分组、分段和窗口结构
5. 链式表达
6. 映射调用与函数模式叠用

## 适用任务

函数已经确定，当前任务是将函数应用到一批元素、二维对象、递推过程、分组结构、窗口结构或多步数据处理链。

## 入口选择

| 任务 | 常用入口 | 判断标准 |
| --- | --- | --- |
| 逐项遍历 | `each` / `:E` | 每个输入项独立处理，结果按位置合并 |
| 保留元组结果 | `loop` / `:U` | 结果必须保持元组形态 |
| 固定左参或右参 | `eachLeft` / `:L`、`eachRight` / `:R` | 一侧参数固定，另一侧参数遍历 |
| 组合左右元素 | `cross` / `:C` | 需要遍历左右两侧组合 |
| 当前项与相邻项组合 | `eachPre` / `:P`、`eachPost` / `:O` | 当前元素需要与前一项或后一项一起计算 |
| 按行处理 | `byRow` / `:H` | 函数按行接收数据，输出按行组织 |
| 按列处理 | `byColumn` / `:V` | 函数按列接收数据，输出按列组织 |
| 全路径递推 | `accumulate` / `:A` | 需要保留每一步状态 |
| 终值递推 | `reduce` / `:T` | 只需要最终状态 |
| 分组聚合 | `groupby` / `:G` | 每组输出一个压缩结果 |
| 分组等长结果 | `contextby` / `:X` | 每组内部计算，输出与输入等长 |
| 段内计算 | `segmentby` | 已有段边界，需要在段内应用函数 |
| 滚动或滑动窗口 | `rolling`、`moving`、`tmoving`、`window`、`twindow` | 需要按事件数、时间或窗口边界重复应用函数 |
| 映射调用 | `eachAt` / `@`、`at` / `[]` | 需要统一处理函数、字典或数据结构的索引调用 |
| 函数模式叠用 | `:L:R`、`:R:L`、`:E:E` | 需要在多层对象结构中连续指定拆分规则 |

## 1. 逐项或组合应用

适用入口：

- `each` / `:E`
- `loop` / `:U`
- `eachLeft` / `:L`
- `eachRight` / `:R`
- `cross` / `:C`

判断规则：

- 每个输入项独立处理时，优先选择 `each` 或 `:E`。
- 结果必须保留为元组时，选择 `loop` 或 `:U`。
- 一侧输入固定、另一侧输入遍历时，选择 `eachLeft` / `:L` 或 `eachRight` / `:R`。
- 需要左右两侧两两组合时，选择 `cross` 或 `:C`。
- 高阶函数的默认拆分规则为：广义向量按元素拆分，矩阵按列拆分，表按行拆分为字典，字典按键拆分，集合不支持拆分。
- 结果合并规则为：同类型标量合并为向量，同长度同类型向量合并为矩阵，标量字典合并为表，字典拆分后仍合并为字典，其他情况返回元组。
- `loop` 不使用通用合并规则，始终返回元组。
- `consistent=true` 只适用于 `eachLeft`、`eachRight`、`eachPre`、`eachPost`、`accumulate`、`reduce`。只有结果类型和形态稳定时才可使用；后续结果无法转换为首个结果类型时会抛出异常。

### 例 1：对函数名集合生成部分应用函数

```dos
names = `add`sub`mul
v = 1..10
funcByName:U(names).{partial{, v}}:U()
```

函数名来自数据，函数对象由 `funcByName` 获取；集合应用方式由 `:U` 指定，结果保持元组形态。

### 例 2：保留元组结果

```dos
m = matrix(1 2 3 4, 5 6 7 8).rename!(`val1`val2)
loop(asis, m).cumsum()
```

目标结果是一组并列对象，且需要保持元组形态。此时 `loop` 比 `each` 更明确。

### 例 3：表按列拆分后保留表形态

```dos
t = table(1 2 3 as v1, 4 5 6 as v2)
w = 0.4 0.6
each(*, t.flip(), w).flip()
```

表默认按行拆分。需要按列处理且保留表形态时，可先用 `flip` 将表转为字典，处理后再转回表。

## 2. 按行、按列或结构方向处理数据

适用入口：

- `byRow` / `:H`
- `byColumn` / `:V`

判断规则：

- 表、矩阵和普通元组通常更接近列方向组织；数组向量和列式元组通常更接近行方向组织。
- 输入函数是聚合函数时，`byRow` 与 `byColumn` 常产生压缩结果。
- 输入函数是标量函数或向量函数时，结果更常保持原对象的结构或长度。
- 自定义向量函数进入二维对象时，应显式指定 `:H` 或 `:V`，不要依赖隐式行为。
- 对常见聚合函数做行方向计算时，`byRow` 可直接承载基础函数；DolphinDB 对部分内置聚合函数已有优化，不必优先回退到逐个 `rowAvg`、`rowSum`、`rowStd` 这类专用行函数。

### 例 4：比较两张表中不一致的行

```dos
t1 = table(`A`B`C as id, 1000 2000 1000 as qty, 50.5 60.5 100.0 as price)
t2 = table(`A`B`C as id, 1000 2100 1000 as qty, 50.5 60.5 100.0 as price)
eq:V(t1, t2).all:H().not().at()
```

`eq:V` 指定按列比较，`all:H` 指定按行归约。该写法同时明确列级比较和行级判定。

### 例 5：让向量级自定义函数进入表

```dos
def myDemean(x){
    return x - avg(x)
}

t = table(1 2 3 4 as val1, 5 6 7 8 as val2)
myDemean:V(t)
```

`myDemean` 只定义向量语义。作用到表时，`:V` 明确将函数按列应用。

## 3. 递推、累计和相邻关系

适用入口：

- `accumulate` / `:A`
- `reduce` / `:T`
- `eachPre` / `:P`
- `eachPost` / `:O`

判断规则：

- 只需要最终状态时，选择 `reduce` 或 `:T`。
- 需要保留每一步状态时，选择 `accumulate` 或 `:A`。
- 当前元素与前一项组合时，选择 `eachPre` 或 `:P`。
- 当前元素与后一项组合时，选择 `eachPost` 或 `:O`。

### 例 6：递推只输出最终结果

```dos
sum:T(1 2 3 4 5)
```

### 例 7：递推输出完整路径

```dos
add:A(1 2 3 4 5)
```

两种写法的差异在输出长度：`:T` 输出终值，`:A` 输出每一步结果。

## 4. 分组、分段和窗口结构

适用入口：

- `groupby` / `:G`
- `contextby` / `:X`
- `segmentby`
- `rolling`
- `moving`
- `tmoving`
- `window`
- `twindow`

判断规则：

- 每组输出一个结果时，选择 `groupby` 或 `:G`。
- 组内计算后仍需与原输入等长时，选择 `contextby` 或 `:X`。
- 已有段边界时，选择 `segmentby`。
- 固定事件数窗口优先检查 `rolling` 或 `moving`。
- 时间范围窗口优先检查 `tmoving` 或 `twindow`。
- `moving` 与 `tmoving` 属于通用高阶窗口入口，适合承接无法增量计算的聚合函数。若语义能直接落入 `msum`、`tmsum` 等专用滑动函数，应优先考虑专用函数。

### 例 8：按分组子表应用函数

```dos
t = table(1..10 as x, 1 1 1 1 2 2 2 2 2 2 as z, rand(1.0, 10) as y1, rand(1.0, 10) as y2, rand(1.0,10) as y3)
each({f->corr:R(f.x, f[`y1`y2`y3])}, t @ groups(t.z, 'tuple'))
```

`groups` 生成分组子表，`each` 将函数应用到每个子表。该写法适合分组结果需要保留为对象集合的场景。

## 5. 链式表达

适用入口：

- `obj.foo(args...)`
- 函数模式配合链式表达
- 短 lambda 嵌入链式流程

判断规则：

- 多步处理存在明确顺序时，优先使用链式表达。
- 链内局部变换较短时，可使用 lambda。
- 嵌套高阶函数影响阅读顺序时，改用函数模式。

### 例 9：数据清洗链式处理

```dos
t = table(["090030020", "090031240", "090032002", "090033284"] as time,
          [1.19, , 1.13, 1.14] as v1, [1.41, 1.45, 1.49, 1.5] as v2)

t.replaceColumn!("time", t.time.temporalParse("HHmmssSSS"))
  .update!("v2", t.v2.winsorize(0.3))
  .at(t.isValid().rowAnd())
```

链式表达使时间解析、列修正和行过滤按执行顺序呈现。

### 例 10：链式表达中嵌入 lambda

```dos
t = table(1 2.5 1.5 4 3 as v1, 1.5 2 2.5 2 3 as v2)
t.zscore().{x->x * x + x + 1}:V()
```

lambda 承载局部列变换，`:V` 指定按列应用。

### 例 11：过滤含有效数据的行

```dos
t[t.values()[1:].isValid().rowOr()]
```

表达式依次完成列值抽取、有效性判定、行级归约和表过滤。

## 6. 映射调用与函数模式叠用

适用入口：

- `eachAt` / `@`
- `at` / `[]`
- 函数模式叠用，例如 `:L:R`、`:R:L`、`:E:E`

判断规则：

- 映射对象可以是函数、字典、向量、矩阵或表。
- `eachAt` / `@` 对多维索引的每一维分别处理，结果通常保留分层结构。
- `at` / `[]` 将索引整体处理。映射对象为函数时，`at` 等价于按实参集合调用函数。
- 多个函数模式叠用时，从左到右依次解释。顺序变化会改变遍历顺序和结果排列。

### 例 12：`eachAt` 对多维索引逐维处理

```dos
d = dict(1 2 3, [1 2, (1 3 5, 2 4 6), 7 8])
eachAt(d, (2, 1, 1))
```

`eachAt` 将元组中的每一项作为一个索引维度分别处理，结果保持为元组。

### 例 13：`at` 将索引作为整体处理

```dos
at(corr, (1 2 3, 4 5 6))
at(d, (2, 1, 1))
```

映射对象为函数时，`at` 将第二个参数作为实参集合；映射对象为字典或数据结构时，`at` 将第二个参数作为整体索引。

### 例 14：函数模式叠用控制排列顺序

```dos
params =  [10, 20, 500]
funcs = [add{1}, sub{,1}, max{1}, min{1}]
makeCall:L:R(funcs, params).flatten()
makeCall:R:L(funcs, params).flatten()
```

`:L:R` 与 `:R:L` 使用相同的函数和参数，但遍历顺序不同，生成结果的排列也不同。

### 例 15：多层结构中叠用 `:E`

```dos
v = matrix(100 200 100, 200 100 200, 100 200 100)
mask = matrix(1 2 1, 1 1 2, 1 2 1)
eachAt:E(v, groups:L(mask, 'tuple')).avg:E:E()
```

第一层 `:E` 处理每列分组下标，后续 `avg:E:E` 对二维元组中的每个分组取均值。

## 选择清单

处理“函数作用在数据上”的任务时，按以下顺序判断：

1. 输入对象是逐项处理、行列方向处理、递推处理，还是分组 / 窗口处理。
2. 输出是逐项结果、终值结果、全路径结果、分组结果，还是窗口结果。
3. 当前函数是否已经定义目标对象上的默认行为。
4. 任务是否存在专用分组或窗口入口。
5. 是否需要用函数模式保持链式表达。
6. 是否涉及映射对象索引调用，需在 `eachAt` 和 `at` 之间选择。
7. 是否存在函数模式叠用，需说明每一层模式处理的对象。
