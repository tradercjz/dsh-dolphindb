# 特征指南

默认目标：

- 对分类、回归和聚类任务，默认尽量多构造“安全候选特征”，再通过泄漏检查、特征对齐、方差/相关性/模型需要进行筛选。
- “多构造”不等于无边界堆特征：任何使用标签、未来时间、测试集统计量、实体唯一标识或高基数泄漏代理的特征都必须排除。

默认构造顺序：

1. 数值测量特征。
2. 缺失指示、异常/阈值标记和布尔/整数标记。
3. 数值变换：平方、`log1p(abs(x))`、`sqrt(abs(x))`、winsorize、标准化/归一化。
4. 低基数类别 one-hot 或明确状态标记。
5. 从主时间列派生的日历、周期和工作日特征。
6. 数值交互：差值、比值、乘积，仅限样本量和业务语义可解释的少量组合。
7. 仅对有序时间粒度表使用滞后、滚动、变化量和历史聚合特征。

排除：

- 标签列
- 标签窗口内的结果字段
- 标签直接组成字段
- 等价未来目标字段
- 实体标识符
- 原始时间列
- 文本状态字段
- 高基数标识符

聊天输出必须说明已选特征、被排除的角色列，以及是否使用了时间派生特征。特征工程阶段完成后必须停止并向用户确认，不直接进入分类、回归或聚类。

特征工程不能承担监督标签定义职责。若原始数据阶段尚未完成未来窗口标签物化，应先回到原始建模数据选择阶段，而不是在特征工程中临时生成或移动标签。

## 脚本块选择策略

- 先运行数值候选和排除原因块，明确哪些列可用、哪些列因标签、实体、时间、文本或泄漏风险被排除；除非用户要求极简 baseline，否则进入 ML 前应优先构造一批安全扩展特征。
- 缺失率可解释且有业务含义时，增加缺失指示特征；不要用缺失指示替代必要的清洗。
- 线性模型或距离类模型优先使用标准化/归一化块；树模型只在需要统一特征尺度展示时使用。
- 有主时间列时可加入年、月、星期、小时和是否周末；如果任务没有时间语义，不要强行派生日历特征。
- 有小时、星期、月份等周期字段时，优先补充 `sin/cos` 周期编码；树模型可同时保留原始整数，线性/距离模型应优先使用周期编码。
- 低基数无序类别或状态列应尽量构造 one-hot/布尔标记；高基数 ID 不直接 one-hot，只允许作为分组键或历史聚合键。
- 数值列数量不多时，可构造平方、`log1p(abs(x))`、`sqrt(abs(x))`、两两差值/比值/乘积；数量较多时先按业务、缺失率、方差或候选上限选 top-N，避免维度爆炸。
- 实体时序数据可使用 lag 和 rolling avg/min/max/count，但必须确认排序列、实体列和窗口只使用历史数据。
- 特征工程结束必须运行特征摘要块、特征选择报告块和必要的宽特征摘要块，并在聊天中输出特征构建方案、来源列、特征族、数量、排除原因和泄漏检查结论。无论风险高低，都必须询问用户是否确认后继续进入分类、回归或聚类。
- 建模前必须使用 train/predict 特征对齐检查；预测表缺少训练特征时停止并说明缺失列。
- 距离类模型、聚类和线性模型优先使用 winsorize+zscore 或标准化块；树模型可保留原始数值特征，除非用户需要统一尺度。
- 特征数量过多或聚类解释困难时，使用按方差选择 top-N 特征块，并说明这是启发式筛选，不代表因果重要性。
- 月度或周期预测任务使用周期索引特征和月度 lag；未来窗口任务必须确认 lag 和 rolling 只使用预测时点之前的数据。
- 交给 ML 阶段前输出特征选择报告块，明确 keep/exclude 决策、来源列和排除原因。

## 与原始数据阶段的边界

- 原始数据阶段负责定义 `label_column`、预测窗口、标签来源和泄漏排除。
- 特征工程阶段负责在已确认的观测窗口内扩展可预测特征，不重新解释标签含义。
- 如果发现标签同日化、未来字段进入特征或标签来源不清，应停止并要求回到原始数据选择阶段修正。

## 候选扩展上限

- 默认 `webMaxExpandedFeatures=80`，超过时按特征族优先级和可解释性截断：原始数值、缺失指示、日历/周期、低基数 one-hot、标准化、非线性数值变换、交互、历史聚合。
- 两两交互默认只对最多 8 个核心数值列生成；超过时先选方差高、缺失率低、业务含义强或用户指定的列。
- one-hot 默认只对基数不超过 20 的类别列生成；超过时输出跳过原因，改用历史聚合或请求用户确认。
- 任何扩展特征都要记录 `feature_family`、`source_column` 或 `source_columns`、`leakage_risk`、`selection_note`，方便下游模型选择解释。

## 阶段确认输出模板

特征工程阶段结束时，聊天输出必须包含：

- 输入口径：使用的清洗结果变量、样本范围、实体列、时间列、标签/目标列和候选原始特征。
- 构造方案：数值变换、缺失/异常标记、one-hot、日历/周期、交互、lag、rolling、变化量、标准化或筛选规则。
- 构造结果：特征表变量名、行数、总列数、保留特征数、各特征族数量、被截断或跳过的候选数量。
- 排除和泄漏检查：标签列、实体 ID、原始时间列、高基数列、未来窗口或疑似泄漏列的排除原因。
- 对齐和下游建议：train/predict 特征是否对齐，分类/回归/聚类分别建议使用哪些特征族或预处理版本。
- 确认问题：`请确认是否使用上述特征结果继续进入分类/回归/聚类？如需调整，请指出要保留、删除或新增的特征规则。`

## 技术补充

- 所有特征转换必须可复现：缩放均值/方差、分位数、类别词表、低频类别阈值、特征筛选阈值都从 train 学习，并作为规则应用到 val/test/predict。
- 周期时间字段不要只按普通整数解释。小时、星期、月份、季度可用 one-hot、`sin/cos` 周期编码或明确的工作日/周末/节假日标记；如果模型是树模型，保留整数日历特征也可以，但输出中要说明它代表周期顺序而非线性大小。
- 低基数无序类别优先 one-hot；高基数 ID、设备号、订单号、用户号默认排除或只作为分组键。确需使用高基数类别时，先聚合成历史统计特征，并严格使用历史窗口，避免把标签信息编码进去。
- 数值特征按模型选择预处理：线性模型、距离模型、PCA 和聚类默认需要标准化或 robust 缩放；树模型优先保留原始数值，只有为了跨模型比较、聚类画像或异常稳健性才缩放。
- 特征交叉和分箱只在有明确业务假设或模型表达不足时使用。交叉会快速增加维度，必须检查每个交叉桶的样本量；分箱边界应来自 train，不能依据 test 表现反复调整。
- lag、rolling、累计值、最近窗口 vs 基准窗口等时序特征必须同时声明实体列、排序列、窗口长度、是否包含当前行；预测任务默认只允许使用历史窗口，不允许泄漏未来标签或未来状态。
- 特征筛选只在 train 或 train+val 的选型阶段内完成。方差筛选、相关性筛选、模型重要性排序和手工排除都要输出原因；不要把 test 指标用于选择或删除特征。
