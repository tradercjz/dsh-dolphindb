# 模型选择教程

本指南用于 `ddb_ml` 的分类、回归和聚类任务。目标是根据任务类型、数据特征和评估指标选择合适模型和轻量网格。

## 通用流程

1. 识别任务类型：分类、回归或聚类。
2. 检查数据前提：schema、标签或目标、特征数量、样本量、时间列和实体粒度。
3. 确认原始建模数据已经定义目标列、预测窗口、泄漏排除和特征时间截止点；未来窗口标签不能留到模型选择阶段再补。
4. 确认用户已经认可清洗结果和特征工程结果；如果用户尚未确认，不要开始模型选择。
5. 读取对应 DOS 的模型函数可用性块，排除当前运行时不可用的模型。
6. 建立候选模型表，记录 `selectedModelId`、`fallbackModelId`、`candidateModelIds`、选择原因和跳过原因。
7. 使用 train/val/test 切分；有预测语义和时间列时优先 time_based，否则使用 random 并说明原因。
8. 在验证集上执行轻量网格搜索，默认候选上限为 20，超过时截断并记录 `grid_truncated=true`。
9. 用验证集选择最佳候选，再用 train+val 重新训练同类候选，并只在 test 上报告最终指标。
10. 聊天输出必须包含候选模型、网格参数、最佳候选、跳过候选、验证集选择指标、测试集最终指标和风险。

## DolphinDB ML API 约束

- 分类和回归训练函数的训练数据必须先构造成数据源，例如 `webTrainDS = sqlDS(<select * from webTrain>)`，再调用 `randomForestRegressor(webTrainDS, ...)` 或 `randomForestClassifier(webTrainDS, ...)`；不要把内存表 `webTrain` 或 `[webTrain]` 直接传给训练函数。
- 分类和回归预测输入必须是 table。优先使用 `predict(webModel, webVal)`、`predict(webModel, webTest)` 或显式构造的特征 table；不要使用 `predict(webModel, webVal[webFeatureCols])` 这种列切片。
- 分类标签必须是从 0 开始的整数编码。若原始标签是 `SYMBOL`、字符串、布尔语义、`yes/no` 或其他非连续编码，先运行分类标签编码块生成整数标签列，再用编码列训练和评估。
- `gaussianNB` 和 `multinomialNB` 使用特征表/标签向量接口，不使用 `sqlDS, yColName, xColNames` 接口。默认网格只包含 `gaussian_nb`；`multinomial_nb` 只在全部特征为非负计数或频次时手动加入。
- `glm_classifier` 默认不进入网格。若使用完整 one-hot 或强共线特征，GLM 可能出现矩阵奇异；只有确认共线性风险低且需要线性统计解释时再手动加入。
- 聚类输入必须是 table。动态特征列先用 `webClusterX = eval(parseExpr("select " + concat(webFeatureCols, ",") + " from webClusterData"))` 构造，再传给 `kmeans(webClusterX, ...)` 和 `predict(webModel, webClusterX)`。
- 同一类 ML API 连续失败 2 次后，必须停止扩大脚本，先运行最小验证块确认 `sqlDS -> train -> predict` 或 `select feature table -> kmeans -> predict` 的最小链路；最小链路仍失败时，在聊天中说明不确定点和需要查询的函数签名。

## 模型特点和优势区间

分类候选：

- `random_forest`：多棵深树投票/平均，优势是能处理非线性、特征交互和混合尺度表格特征，通常是中小到中等规模表格数据的稳健基线。优先用于特征关系未知、线性模型欠拟合、需要较少缩放假设的任务；慎用于极高维稀疏 one-hot、强外推、严格单调解释或低延迟大网格场景。
- `logistic_regression`：线性分类器，输出概率，支持正则化。优先用于二分类、多 one-hot/稀疏特征、近似线性边界、需要方向解释或概率阈值调节的任务；数值特征应标准化。若特征交互或非线性明显，应补充交叉/分箱或改用树模型。
- `gaussian_nb`：假设每类下连续特征近似高斯且条件独立，训练快、样本需求低。适合作为小样本、快速基线或特征近似独立的连续特征任务；特征强相关、分布严重偏斜或需要高质量概率校准时慎用。
- `multinomial_nb`：适合非负计数、频次或词袋类特征。只在特征语义是计数/频次/强度且没有负值时进入候选；普通连续测量值、标准化后的负值特征或任意整数编码类别不应默认使用。
- `glm_classifier`：带 binomial/logit 的广义线性分类基线，适合需要统计口径、线性可解释和概率输出的二分类。优先用于样本量适中、特征已清洗缩放、业务希望解释系数方向的任务；非线性强、类别很多或类别严重不平衡时需谨慎。
- `adaboost_classifier`：序列式提升弱学习器，后续弱模型更关注难分样本。适合小到中等规模、浅树能逐步修正错误的非线性分类；标签噪声、异常点多或正类定义不稳时容易放大错误，必须检查验证集和风险报告。

回归候选：

- `random_forest`：非线性表格回归默认强基线，适合特征交互、阈值效应、非单调关系和无需线性解释的预测。慎用于训练样本很少、需要范围外外推、要求平滑趋势或严格解释系数的任务。
- `ridge`：L2 正则线性回归，会收缩系数但通常不置零。优先用于数值特征较多、共线性明显、每个特征可能都有弱贡献且需要稳定系数的回归；如果真实信号稀疏且希望自动筛特征，可比较 lasso/elastic_net。
- `lasso`：L1 正则线性回归，可把部分系数压到 0，适合稀疏信号和特征筛选。优势区间是特征很多但真正有效特征较少、特征相关性不强；强相关特征组中可能只随机保留一个，稳定性弱于 ridge/elastic_net。
- `elastic_net`：L1+L2 折中，同时具备稀疏和共线稳定性。优先用于高维且相关特征成组出现的数值回归；当 lasso 过度丢弃相关特征、ridge 又不够稀疏时使用。
- `glm_regression`：广义线性回归，适合目标分布和 link 有明确假设的任务。普通连续目标可用 gaussian/identity 作为可解释线性基线；计数、频率、正偏目标更适合后续扩展为 Poisson/Gamma/Tweedie 思路。强非线性或复杂交互需要特征工程或树模型。
- `adaboost_regressor`：序列提升回归器，后续模型关注误差较大的样本。适合浅树能逐步解释残差的中小表格回归；目标噪声、离群点或标签异常较多时慎用，并重点看 top error 和残差摘要。

聚类候选：

- `kmeans`：基于欧氏距离和质心，优势区间是已标准化的连续数值特征、簇近似凸/球形、k 可在小范围内解释。对尺度、离群点、初始化和非凸/不同密度簇敏感；必须报告簇规模、画像和代表样本，不只看分数。
- `pca_kmeans`：先用 PCA 降维/去相关，再做 kmeans。适合高维、强共线、距离膨胀或特征族很多导致 kmeans 不稳定的场景；优势是降噪和加速，代价是可解释性下降。PCA/缩放参数必须只从 train 或当前聚类输入学习，并报告解释方差或保留维度。

## 分类模型选择

默认候选：

- `random_forest`：表格数据稳健默认，适合非线性、混合尺度和特征交互。
- `logistic_regression`：二分类可解释基线，适合线性边界和需要说明方向的任务。
- `gaussian_nb`：小样本或快速基线，假设特征近似连续分布。
- `multinomial_nb`：非负计数型或频次特征；普通连续特征不默认优先，也不进入默认网格。
- `glm_classifier`：二分类统计基线，适合需要可解释分布假设的任务；默认不进入网格，避免 one-hot 共线性导致矩阵奇异。
- `adaboost_classifier`：非线性候选，适合弱学习器组合，但要关注过拟合。

指标选择：

- 二分类默认用 F1 选型。
- 漏报代价高时用 recall。
- 误报代价高时用 precision。
- 多分类默认用 accuracy，并补充混淆矩阵。

类别不均衡处理：

- 只增加欠采样这一种默认处理方式。先完成 train/val/test 切分，再只对训练集执行欠采样；验证集和测试集必须保持原始类别分布，用于真实评估。
- 当多数类/少数类比例明显偏高，或 accuracy 很高但少数类 recall/F1 很低时，运行 `ddb_ml/scripts/classification_reference.dos` 的“分类训练集欠采样”块，生成 `webTrainForModel` 和 `webFinalTrainForModel`。
- 欠采样后，网格搜索和最终训练应使用 `webTrainForModel` / `webFinalTrainForModel`；报告必须同时说明欠采样前后标签分布、丢弃的多数类样本量，以及少数类 recall/F1 的变化。
- 少数类样本极少时，欠采样会显著减少训练量；此时不要只看 accuracy，应优先用 recall、precision、F1 和混淆矩阵判断是否真正提升模型表现。

## 回归模型选择

默认候选：

- `random_forest`：稳健非线性基线，适合表格回归和特征交互。
- `ridge`：稳定线性基线，适合共线性明显但不希望稀疏化。
- `lasso`：稀疏线性基线，适合想压缩特征或做弱选择。
- `elastic_net`：兼顾共线性和稀疏，适合高维数值特征。
- `glm_regression`：统计基线，适合简单线性和可解释任务。
- `adaboost_regressor`：非线性 boosting 候选，适合残差结构明显的数据。

指标选择：

- 默认用 RMSE 选型。
- 异常值影响过大时用 MAE。
- 需要解释方差解释度时补充 R2。
- 目标含 0 或接近 0 时，MAPE 只能作为参考并说明失真风险。

旧版 registry 的 `lambda` 在当前 Web DOS 中映射到线性模型的 `alpha`；旧版 elastic net 的 `alpha` 映射到当前 `l1Ratio`。

## 聚类模型选择

默认候选：

- `kmeans`：标准化连续特征上的默认模型。
- `pca_kmeans`：高维、强共线或特征族大量展开时的候选；只有当前运行时支持 PCA 投影时才执行，否则记录跳过。

指标选择：

- 默认用近似分离度或簇规模平衡度选型。
- 不盲目选择最高分；必须同时满足没有明显塌缩、极小簇可解释、簇画像可读。
- 业务解释不清楚时，优先选择较小且稳定的 k。

## 网格搜索边界

- 默认 `candidateLimit=20`。
- 网格报告必须包含 `candidate_id`、`status`、`error_message`、`model_id`、`model_function`、`params_json`、`selection_metric`、`selection_score`、`rank`、`is_best`、`candidate_elapsed_ms`。
- 模型选择摘要必须包含 `grid_candidate_limit`、`grid_candidate_total_estimated`、`grid_truncated`。
- 样本不足、切分为空、标签单一、函数不可用或用户要求只用单模型时，可以跳过网格搜索，但必须写明跳过原因。

## 技术补充

- test 只能使用一次作为最终报告口径。模型类型、特征、清洗规则、阈值和网格参数都必须在 train/val 或交叉验证内确定；如果根据 test 结果继续调参，必须重新划分或明确说明 test 已被污染。
- 有时间顺序或未来预测语义时，默认使用 time_based 切分，保证 train 时间早于 val，val 早于 test。不要随机打散会造成未来信息进入训练集的样本。
- 分类任务类别不均衡时，切分前先看标签分布；随机切分应尽量保持正负类或多类别分布。正类稀少时，不要只用 accuracy 选型，优先按 recall、precision、F1 或业务代价选择；需要处理不均衡时，只对训练集使用欠采样块，不改验证集和测试集。
- 同一实体、设备、用户或批次的多行记录可能产生泄漏。若目标是泛化到新实体，应按实体分组切分；若目标是未来预测，应按时间切分并避免同一未来窗口跨 train/val/test。
- 网格搜索从小候选开始，优先覆盖不同模型族和关键超参数，而不是穷举大网格。每个候选都记录成功、失败、跳过原因和耗时；连续 API 或数据前提失败时先最小验证，不继续扩展网格。
- 选型时同时检查训练集与验证集差距。训练分数高、验证分数低表示过拟合，优先降低模型复杂度、加强正则、减少泄漏特征或改用更稳健的切分。
- 回归报告至少给出 MAE、RMSE 和 R2；目标含 0 或接近 0 时 MAPE 只作为辅助。分类报告至少给出标签分布和混淆矩阵；聚类报告不能只给分数，还要给簇规模、代表样本和特征画像。
- 最佳候选必须能解释为什么适合当前任务：样本量、特征类型、是否非线性、是否需要缩放、是否抗异常、是否支持当前运行时函数。不可用或不适合的模型要保留跳过原因。
