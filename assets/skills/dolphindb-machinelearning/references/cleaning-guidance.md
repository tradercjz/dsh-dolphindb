# 清洗指南

默认清洗策略应保持保守：

- 只有当重复行不是有意义事件时，才删除完全重复行。
- 对监督学习，删除标签为空的训练行。
- 当模型不能处理缺失值时，用中位数或均值填充数值特征缺失值。
- 先标记异常值，再考虑删除；只有用户或领域规则明确要求时才删除。
- 只有当无效值语义明确时，才使用质量/状态列做过滤。

聊天输出必须包含源行数、输出行数、已应用步骤、跳过步骤和警告。清洗阶段完成后必须停止并向用户确认，不直接进入特征工程或建模。

## 脚本块选择策略

- 先运行清洗前基线块，记录行数、列数和整体缺失情况，作为后续对比口径。
- 缺失值问题先用缺失率统计块定位列；只有影响建模、聚合或用户目标时才选择填充块。
- 重复问题先区分完全重复行和业务 key 重复；业务 key 重复不能直接删除，必须说明可能语义。
- 数值缺失默认优先中位数填充；近似正态或用户指定时可用均值；设备/实体差异明显时用分组中位数。
- 异常值默认先标记 IQR 或 z-score，不直接删除；需要稳定训练输入时可使用 winsorize 裁剪。
- 清洗结束必须运行清洗摘要块，对比行数、列数、缺失率变化、删除/填充/标记数量。无论风险高低，都必须输出“清洗方案 + 清洗结果 + 跳过步骤 + 警告”，并询问用户是否确认后继续进入特征工程或建模。
- 当角色推断输出 `timeseries_sensor` 或存在质量/单位/点位角色时，优先补充质量码无效标记、单位标准化建议、时间间隔缺失风险和 stuck/jump 信号异常块。
- 当角色推断输出 `production_record`、`quality_record` 或用户指定业务 key 时，先生成业务 key 重复决策表；只有用户确认压缩规则后才使用“保留最优记录”块。
- 标签编码映射只在分类模型需要数值/稳定标签时使用；输出映射后要求用户确认正类或类别含义。
- 清洗风险和警告摘要是清洗阶段的结束块；若出现高缺失、质量码无效、时间间隔风险或信号异常，必须在确认问题中突出风险。即使没有风险，也要等待用户确认清洗结果。

## 阶段确认输出模板

清洗阶段结束时，聊天输出必须包含：

- 数据范围：库表、过滤条件、原始行数/列数、清洗后行数/列数。
- 清洗方案：实际执行的删除、填充、标记、裁剪、质量码处理、单位处理、去重或标签编码步骤。
- 清洗结果：每个步骤影响的行数/列数、缺失率变化、异常/无效/重复记录数量、生成的中间结果变量名。
- 跳过步骤：为什么没有执行某些候选清洗，例如没有缺失、没有重复 key、质量码语义不明或用户未确认。
- 风险和警告：潜在语义改变、数据量损失、标签/时间泄漏、质量码或业务 key 风险。
- 确认问题：`请确认是否使用上述清洗结果继续进入特征工程/建模？如需调整，请指出要改的清洗规则。`

## 技术补充

- 任何会学习数据统计量的清洗步骤都必须遵守切分边界：均值/中位数填充、分位数裁剪、z-score 标准化、缺失指示阈值、低频类别归并阈值只能从 train 统计，再把同一常量或规则应用到 val/test/predict。不要先在全量数据上学习这些规则再切分。
- 缺失值处理先分三类：标签缺失的训练行通常删除；关键实体/时间/连接键缺失时停止确认；普通特征缺失优先填充并保留缺失率和填充值来源。整列全空、近乎全空或常量列应默认排除，并在摘要中说明。
- 如果缺失本身有业务含义，保留 `is_missing_*` 指示列；但不要用缺失指示替代必要的数据质量检查。预测表出现训练时未见的全空特征时，应停止或回退到已确认的填充规则。
- 异常值不要默认删除。对线性、距离、聚类或需要稳定数值范围的模型，优先使用基于 train 分位数的 winsorize 或 IQR 标记；对树模型可先保留原始值并输出异常画像。
- 类别清洗要固定词表：低基数类别可保留，低频或未知类别归入 `OOV/other`；不要把无序类别直接映射成连续整数后交给线性、距离或聚类模型。
- 时间序列清洗不得用未来值填充过去。前向填充、插值、滚动统计和时间间隔修复必须按实体和时间排序，并确认只使用预测时点之前的数据。
